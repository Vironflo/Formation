## Pourquoi ce format

Une formation de deux jours d'affilée produit de l'enthousiasme le vendredi et un oubli complet
le lundi suivant. Le forfait fractionné change la dynamique :

- Chaque session se termine par une **mise en pratique sur vos vrais projets**
- Entre deux sessions, vous testez — et vous revenez avec de vraies questions
- Les heures restantes servent à débloquer, pas à réciter un programme

---

## Les thématiques abordées (à la carte)

Nous piochons dans ces thématiques au fil des sessions, en avançant à votre rythme.

### 1. Installation et prise en main

- Compréhension de base de Visual Studio Code
- Mise en place de Claude Code sur votre machine, simplement
- Différences avec la version web, et pourquoi le terminal change tout
- Configuration de base pour être opérationnel dès la première heure

### 2. Méthodologie et productivité

- Formuler ses demandes pour obtenir le bon résultat du premier coup
- Fournir du contexte à l'IA : fichiers, documentation, captures d'écran
- Gérer les longues conversations sans perdre le fil
- Savoir quand relancer une session propre plutôt que d'insister

### 3. L'IA comme binôme de développement

- **Génération** — bases de code, scripts, templates, structures de projet
- **Analyse** — comprendre en 5 minutes un code hérité qu'on n'a pas écrit
- **Débogage** — identifier la cause réelle d'une erreur, pas seulement le symptôme
- **Refactoring** — nettoyer, commenter, optimiser l'existant sans rien casser
- **Automatisation** — déléguer au terminal les tâches répétitives

## Les options — nice to have

Ces briques ne sont pas indispensables au démarrage. Elles se déclenchent quand le socle
est acquis, et se prennent sur les heures du forfait ou en extension.

- **Mémoire projet configurée** — un fichier de règles par projet : conventions de code,
  stack technique, procédures de déploiement. L'IA arrive briefée à chaque session, plus besoin
  de tout réexpliquer.
- **Commandes personnalisées** — vos procédures récurrentes transformées en raccourcis
  (`/revue`, `/deploy-check`, `/audit-secu`). Ce qui prenait dix minutes d'explication devient
  un mot.
- **Automatisations déclenchées** — formatage automatique après chaque modification,
  vérifications avant commit, notifications de fin de tâche.
- **Connexion à vos outils** — accès direct à vos dépôts, votre documentation,
  vos bases de données ou vos tickets, depuis la conversation.
- **Sessions d'équipe** — diffuser la pratique au-delà d'une seule personne, avec une
  configuration partagée et versionnée.
- **Support post-formation** — un canal pour les questions qui surgissent en conditions réelles,
  là où elles comptent vraiment.

## La plus-value concrète

Ce que vous gagnez, formulé en résultats plutôt qu'en fonctionnalités.

### Du temps, sur des tâches identifiables

- Comprendre un code existant : de plusieurs heures à quelques minutes
- Rédiger la documentation d'un module : de fastidieux à généré puis relu
- Écrire un script d'automatisation ponctuel : de « je le ferai un jour » à fait dans la journée
- Reprendre un projet laissé de côté : le contexte est reconstitué par l'IA, pas par votre mémoire

### De l'autonomie sur des sujets bloquants

Les tâches qu'on repousse parce qu'elles demandent une compétence qu'on n'a pas encore
(un langage inconnu, une configuration serveur, une expression régulière tordue)
deviennent accessibles avec un binôme qui explique en avançant.

### De la qualité, pas seulement de la vitesse

Un code relu systématiquement, commenté, testé — parce que le coût de le faire s'effondre.
La dette technique se rembourse quand elle cesse d'être douloureuse à traiter.

### Une compétence qui reste

L'objectif n'est pas que vous dépendiez de moi, ni de l'outil. C'est que vous sachiez
**quand l'IA aide, quand elle nuit, et comment vérifier ce qu'elle produit.**
Cette compétence-là résiste aux changements de version et d'éditeur.
